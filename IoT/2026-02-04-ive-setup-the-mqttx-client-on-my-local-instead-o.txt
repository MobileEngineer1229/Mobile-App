  Here's how it works (lines 340-375 in mqtt-auth-routes.ts):

  Register Device Flow:
  1. Generate credentials via EmqxApiService
  2. Create credentials in EMQX broker
  3. Save to database with metadata:
     {
       protocol: 'mqtt',
       productId: '1001',
       deviceNum: 'ABC123',
       mqttPassword: 'generated_password',  ← stored here
       registeredAt: '...',
     }

  Current storage:
  ┌───────────┬───────────────────────────────────────────────┐
  │   Field   │                 Where Stored                  │
  ├───────────┼───────────────────────────────────────────────┤
  │ username  │ Derived: device-{deviceNum} (not stored)      │
  ├───────────┼───────────────────────────────────────────────┤
  │ password  │ metadata->>'mqttPassword' (JSONB)             │
  ├───────────┼───────────────────────────────────────────────┤
  │ client_id │ Derived: {productId}-{deviceNum} (not stored) │
  └───────────┴───────────────────────────────────────────────┘
  Auth webhook (line 43-68) validates by:
  1. Extract deviceNum from username (device-ABC123 → ABC123)
  2. Query: SELECT metadata FROM devices WHERE metadata->>'deviceNum' = $1
  3. Compare metadata.mqttPassword with provided password

  So it works, but:
  - No dedicated mqtt_username, mqtt_password, mqtt_client_id columns
  - Harder to query/manage credentials
