> 이 문서는 조선민주주의인민공화국 조선말(북한어)로 작성한 기술 안내서입니다.  
> 음식과 운동 분야에 특화된 언어 모형을 처음부터 학습시키는 전 과정을 담고 있습니다.

## 1. 프로그람 개요

이 체계는 조선말 전용 언어 모형을 밑바닥부터 구축하는 프로그람입니다.  
외부 사전 학습 모형(GPT-4, LLAMA 등)을 사용하지 않고, 사용자가 제공하는 조선말 자료로만 학습합니다.

**주요 기능:**
- 음식(료리법) 및 운동(체육 계획) 분야 문답 대화
- 그라디오(Gradio) 웹 화면을 통한 3가지 대화 방식 제공
  - 자유 대화
  - 료리 추천
  - 운동 계획
- RTX 5070 같은 현대 그라픽 처리 장치에서 고속 학습

**기술 구성:**
| 항목 | 내용 |
|------|------|
| 언어 | Python 3.10+ |
| 심층학습 틀 | PyTorch 2.7+ (CUDA 12.8) |
| 어표 분석기 | SentencePiece BPE |
| 웹 화면 | Gradio 6.14+ |
| 자료 구조 | numpy.memmap 이진 파일 |

## 2. 체계 구조 (모형 설계)

### 2-1. 변환기(Transformer) 구조

이 모형은 **GPT 방식의 단방향 변환기**입니다. 입력 글자들을 왼쪽에서 오른쪽 순서로만 처리하며, 다음 글자를 예측하는 방식으로 학습합니다.

```
입력 글자열
    ↓
어표 삽입(Token Embedding) + 위치 삽입(Positional Embedding)
    ↓
변환기 블록 × 8층
    각 층 = {주목 기제(Multi-Head Attention) → 정규화 → 순방향 신경망(FFN) → 정규화}
    ↓
출력 사영(Linear) → 어휘 확률 분포
    ↓
다음 어표 선택(표본 추출)
```

### 2-2. 기본 설정값 (30M 매개변수 모형)

| 설정 | 값 | 설명 |
|------|----|------|
| `n_layer` | 8 | 변환기 블록 수 |
| `n_head` | 8 | 주목 머리 수 |
| `n_embd` | 512 | 은닉 벡터 차원 |
| `ffn_dim` | 2048 | 순방향 신경망 내부 차원 (= 4 × n_embd) |
| `block_size` | 1024 | 최대 문맥 길이(어표 수) |
| `vocab_size` | 16384 | 어휘 크기 |
| `dropout` | 0.1 | 탈락 비율 |
| `tie_weights` | true | 입출력 사영 가중치 공유 |

> **100기가 자료 학습 시 권장 설정 (85M 매개변수):**  
> `n_layer: 12`, `n_head: 12`, `n_embd: 768`, `ffn_dim: 3072`

### 2-3. 주목 기제 (Attention)

각 주목 머리는 입력 벡터를 3개의 행렬(Q, K, V)로 변환하고 주목 점수를 계산합니다:

```
주목 점수 = softmax(Q × Kᵀ / √d_head) × V
```

인과적 마스크(Causal Mask)를 사용하여 현재 위치보다 앞선 위치의 정보만 참고합니다.

### 2-4. 순방향 신경망 (FFN)

각 변환기 층의 두 번째 부분:
```
FFN(x) = GELU(x × W₁ + b₁) × W₂ + b₂
```
W₁: 512 → 2048, W₂: 2048 → 512

## 3. 어표 분석기 학습

### 3-1. SentencePiece BPE

조선말은 교착어(어미와 조사가 풍부)이므로, 형태소 분석 없이 원문자에서 직접 작동하는 **BPE(두글자 쌍 부호화)** 방식을 사용합니다.

**BPE 원리:**
1. 모든 글자를 개별 단위로 시작
2. 가장 자주 나타나는 인접 글자 쌍을 합쳐 새 단위 생성
3. 목표 어휘 크기에 도달할 때까지 반복

예: `료리법` → `['▁료', '리', '법']` (세 어표)

### 3-2. 특수 어표

| 어표 ID | 의미 | 용도 |
|---------|------|------|
| 0 | PAD | 묶음 채우기 |
| 1 | BOS | 문장 시작 |
| 2 | EOS | 문장 끝 |
| 3 | UNK | 미지 어표 |

**주의:** UNK 어표(⁇ 기호)는 출력 시 자동으로 걸러냅니다.

### 3-3. 어휘 크기 자동 조정

소량 자료(수천 글자 미만)에서는 큰 어휘 크기를 사용할 수 없습니다.  
프로그람이 자동으로 계산합니다:

```
최대_가능_어휘_크기 = max(100, 고유_글자_수 × 6)
실제_어휘_크기 = min(설정_어휘_크기, 최대_가능_어휘_크기)
```

자료가 충분(100기가)하면 설정값 16,384가 그대로 적용됩니다.

```powershell

python -m src.tokenizer.train_tokenizer --config config/model_config.yaml
```

결과: `checkpoints/tokenizer/dprk_sp.model`

## 5. 모형 학습

### 5-1. 학습 알고리듬

**AdamW 최적화기** + **코사인 학습률 감쇠** 조합:

```
학습 초기 (온기 단계): 학습률 0 → 3.0e-4  (100 스텝)
학습 중기 (감쇠 단계): 학습률 코사인 감소  (100 → 5000 스텝)
학습 말기 (최솟값):   학습률 3.0e-5        (5000 스텝 이후)
```

### 5-2. 기울기 누적 (Gradient Accumulation)

그라픽 처리 장치 기억 한계를 극복하기 위한 기법입니다:

```
실효 묶음 크기 = batch_size × grad_accum_steps × block_size
              = 16 × 4 × 1024 = 65,536 어표/스텝
```

4번의 소묶음 순방향 계산 후 1번의 역전파와 매개변수 갱신을 수행합니다.

### 5-3. 혼합 정밀도 (bf16)

RTX 5070(Blackwell 구조)은 `bfloat16` 연산을 고속 지원합니다:
- 기억 사용량: float32의 절반
- 속도: float32 대비 약 2~3배
- 정확도: float16보다 수치 안정성 우수

## 7. 강제 종료 처리 (전원 차단)

### 7-1. 기술적 설명

중간저장 코드 (`src/train/utils.py:34`):
```python
torch.save({...}, path)
```

`torch.save()`는 임시 파일을 거치지 않고 직접 대상 파일에 씁니다.  
따라서 저장 **도중** 전원이 차단되면 해당 파일이 손상될 수 있습니다.

### 7-2. 실제 영향

| 상황 | 영향 |
|------|------|
| 저장 완료 후 전원 차단 | 영향 없음 — 파일 정상 |
| 저장 도중 전원 차단 | 해당 파일 손상 가능 |
| 학습 도중(저장 시점 아님) 전원 차단 | 영향 없음 — 이전 저장 파일 정상 |

### 7-3. 안전 장치

`ckpt_keep_last: 3` 설정으로 최근 3개의 중간저장점이 항상 보존됩니다:
```
checkpoints/
├── ckpt_step000250.pt   ← 250 스텝 (가장 오래됨)
├── ckpt_step000500.pt   ← 500 스텝
├── ckpt_step000750.pt   ← 750 스텝 (가장 최신)
└── ckpt_step002500_best.pt  ← 최고 성능 (항상 보존)
```

### 7-4. 손실 규모

- 중간저장 주기: `eval_interval: 250` 스텝
- RTX 5070 속도: 약 130,000 어표/초
- 250 스텝 = 16×4×1024×250 = 16,384,000 어표 처리
- 소요 시간: 16,384,000 ÷ 130,000 ≈ **126초 (약 2분)**

**결론: 강제 종료 시 최대 2분치 학습이 손실됩니다.**

### 7-5. 복구 방법

강제 종료 후 콤퓨터를 재시작하면:

```powershell
# 1단계: 중간저장점 목록 확인
ls checkpoints\ckpt_step*.pt

# 2단계: 손상 여부 확인 (파일 크기가 비정상적으로 작으면 손상)

# 3단계: 마지막 정상 파일로 재시작

```

## 8. 추론과 대화

### 8-1. 표본 추출 알고리듬

학습된 모형에서 다음 어표를 고르는 과정:

**온도 조절 (Temperature):**
```
확률 = softmax(로짓 / 온도)
```
- 온도 = 1.0: 원래 확률 그대로
- 온도 < 1.0: 확률 차이 강조 (더 일관된 출력)
- 온도 > 1.0: 확률 차이 완화 (더 창의적인 출력)

**상위 K 표본 (Top-k):**
확률 높은 상위 50개 어표만 남기고 나머지 제거 후 표본 추출

**핵 표본 (Top-p / Nucleus Sampling):**
누적 확률이 95%에 도달할 때까지 어표 추가 후 표본 추출

**반복 억제 (Repetition Penalty):**
이미 생성한 어표의 확률을 계수(1.15)로 나누어 반복 방지

### 8-2. 대화 흐름

```
사용자 입력 → 시스템 접두사 + 대화 이력 + 새 입력 결합
    ↓
어표화 (최대 block_size=1024 어표로 자름)
    ↓
모형 순방향 계산 → 로짓 벡터
    ↓
온도/top-k/top-p/반복 억제 적용
    ↓
어표 선택 → 문자열로 변환 → 화면에 표시
    (EOS 어표 또는 max_new_tokens 도달까지 반복)
```

### 8-3. 시스템 접두사

모형이 충분히 학습되면(어휘 크기 ≥ 8,000) 역할 접두사를 붙입니다:

| 대화 방식 | 접두사 |
|-----------|--------|
| 자유 대화 | `당신은 음식과 운동에 대해 안내하는 조선말 조수입니다.` |
| 료리 추천 | `당신은 조선식 료리법 안내 조수입니다. ...` |
| 운동 계획 | `당신은 운동 계획 안내 조수입니다. ...` |

## 9. 100기가 자료 학습 안내

### 9-1. 권장 모형 크기

| 자료 크기 | 권장 모형 | 매개변수 | 학습 스텝 |
|-----------|-----------|----------|-----------|
| 1MB 미만 | 기본 설정 | 30M | 5,000 |
| 1~10GB | 중간 설정 | 50M | 50,000 |
| 10~100GB | 대형 설정 | 85M | 200,000+ |

### 9-2. 85M 모형 설정

`config/model_config.yaml`에서 아래와 같이 수정하십시오:

```yaml
model:
  n_layer: 12
  n_head: 12
  n_embd: 768
  ffn_dim: 3072
  block_size: 1024
  vocab_size: 16384
  dropout: 0.1
  tie_weights: true

train:
  batch_size: 8          # 큰 모형이므로 묶음 크기 줄임
  grad_accum_steps: 8    # 실효 묶음 크기 유지
  max_steps: 200000
  eval_interval: 1000
  ckpt_keep_last: 5
```

### 9-3. 예상 학습 시간

**RTX 5070 (12GB VRAM) 기준:**

| 자료 | 어표 수 | 속도 | 예상 시간 |
|------|---------|------|----------|
| 10GB | ~50억 어표 | 130k tok/s | 약 11시간 |
| 100GB | ~500억 어표 | 130k tok/s | 약 4.5일 |

> 실제로는 200,000 스텝 기준:  
> 200,000 × 8 × 8 × 1024 ÷ 130,000 ÷ 3600 ≈ **28시간**  
> (전체 자료를 여러 번 반복하지 않는 1 에폭 기준)

### 9-4. 자료 제공 방법

```
AI-assistant/data/raw/ 폴더에 자료 파일을 넣으십시오.
지원 형식: .txt, .jsonl
하위 폴더도 자동으로 처리됩니다.
```

## 11. 문제 해결

이 절에서는 실제 실행 중 만난 오류들과 해결 방법을 정리합니다.

### 오류 1: 어휘 크기 초과

**오류 메시지:**
```
RuntimeError: Vocabulary size too high (16384). Please set it to a value <= 2333
```

**원인:** 자료가 너무 적어 요청한 어휘 크기를 만들 수 없음

**해결:** 프로그람이 자동으로 어휘 크기를 조정합니다.  
자료를 더 추가하면 큰 어휘를 사용할 수 있습니다.

---

### 오류 2: 자료 크기 부족

**오류 메시지:**
```
ValueError: Dataset has 156 tokens but block_size is 1024
```

**원인:** 전처리된 자료 어표 수가 문맥 길이보다 작음

**해결:** 프로그람이 자동으로 `block_size`를 줄입니다.  
자료를 더 추가하는 것이 근본 해결책입니다.

---

### 오류 3: Windows 포트 차단

**오류 메시지:**
```
OSError: [WinError 10013] Cannot find empty port in range: 7860-7860
```

**원인:** Windows 11의 Hyper-V/WSL이 7787~7886 포트를 예약

**해결:** `scripts/04_run_app.ps1`에서 포트를 8000으로 지정

```powershell
python -m src.app.gradio_app --server-port 8000
```

---

### 오류 4: localhost 접속 불가

**증상:** 프로그람은 실행되는데 브라우저에서 접속 안 됨

**원인:** Windows 11이 `localhost`를 IPv6(::1)로 해석함

**해결:** `http://127.0.0.1:8000`으로 직접 접속  
`gradio_app.py`에서 `server_name="127.0.0.1"` 설정됨

---

### 오류 5: 출력에 ⁇ 기호 나타남

**증상:**
```
⁇ 4.: ⁇ 4.육 보기
```

**원인:** 소량 자료로 학습된 어표 분석기가 시스템 접두사 글자를 처리하지 못함

**해결:**
1. `tokenizer.py`에서 UNK 어표 자동 제거됨
2. 어휘 크기 8,000 미만이면 시스템 접두사 생략됨
3. 근본 해결: 자료를 늘려 어휘 크기 증가

---

### 오류 6: 대화 제출 시 서버 충돌 (Gradio 6)

**원인:** Gradio 6은 대화 이력 형식이 변경됨  
이전: `[["사용자", "조수"], ...]` (쌍 목록)  
현재: `[{"role": "user", "content": "..."}, ...]` (사전 목록)

**해결:** `gradio_app.py`를 Gradio 6 형식으로 완전히 재작성함 ✓

---

### 오류 7: RTX 5070 (Blackwell) 호환성

**원인:** RTX 5070은 Compute Capability 12.0 (sm_120)  
PyTorch 2.7 미만에서는 미지원

**해결:**
```powershell
pip install torch==2.7.0+cu128 --index-url https://download.pytorch.org/whl/cu128
```

---

### 오류 8: PowerShell 스크립트 오류 (SentencePiece 로그)

**원인:** `$ErrorActionPreference = "Stop"` 설정 시 SentencePiece  
정보 메시지를 오류로 인식

**해결:** 모든 스크립트에서 `$LASTEXITCODE` 기반 검사로 교체 ✓

## 12. 참고 사항

### 손실 함수 해석

| 검증 손실 | 의미 |
|-----------|------|
| 9~10 | 학습 시작 단계 (무작위 수준) |

### 학습 자료와 품질 관계

- **수천 문장:** 언어 패턴 파악, 어색한 출력
- **수십만 문장 (수백MB):** 기본 문답 가능
- **수백만 문장 (수GB):** 자연스러운 대화 가능
- **수억 문장 (100GB):** 전문가 수준 조선말 생성

### 조선말 특성

이 모형은 표준 한국어(남측)가 아닌 **조선말(북측)** 전용입니다:
- `프로그램` → `프로그람`
- `컴퓨터` → `콤퓨터`
- `알고리즘` → `알고리듬`
- `인터넷` → `인터네트`
- `소프트웨어` → `쏘프트웨어`

학습 자료를 조선말 원문으로 제공할수록 모형의 조선말 품질이 향상됩니다.
