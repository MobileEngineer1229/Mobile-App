## 1. 핵심 원칙 — 현현기억기는 절대적 한계선

> **현현기억기(VRAM)는 절대적 한계선입니다.**  
> 학습 실행의 전체 기억 점유량이 12 GB를 초과하면,  
> 처리 속도가 떨어지는 것이 아니라 **즉시 충돌(OOM 오류)하며 멈춥니다.**

```
OOM = Out of Memory (기억기 초과 오류)
```

이 한계는 협상할 수 없습니다. 그라픽 처리 장치는 현현기억기 안에 있는 자료만 처리할 수 있으며, 용량을 초과하는 순간 학습 과정 전체가 강제 종료됩니다. 느려지거나 경고를 표시하는 것이 아니라 즉시 멈춥니다.

## 2. 학습 중 현현기억기에 무엇이 저장되는가

학습(처음부터 신경망을 훈련하는 것)은 추론(이미 만들어진 모형으로 대답을 생성하는 것)과 근본적으로 다릅니다.

학습 도중에는 **매개변수 하나하나에 대해 동시에 네 가지 정보**를 현현기억기에 보관해야 합니다:

| 보관 항목 | 자료형 | 매개변수당 바이트 | 리유 |
|-----------|--------|------------------:|------|
| 모형 가중치 | bf16 | 2 | 신경망 자체 — 학습된 값들 |
| 기울기 | bf16 | 2 | 역전파에서 계산한 손실 변화율 (dLoss/dWeight) |
| 아담 1차 모멘트 (기울기 평균) | fp32 | 4 | 최적화기 상태 1번 — 과거 기울기의 이동 평균 |
| 아담 2차 모멘트 (기울기 제곱 평균) | fp32 | 4 | 최적화기 상태 2번 — 과거 기울기 제곱의 이동 평균 |
| **기본 합계** | | **12** | 활성화값 제외 |

**그 위에 활성화값이 추가됩니다.** 활성화값이란 순방향 계산 시 각 층에서 생성되는 중간 출력값으로, 역전파 때 기울기를 계산하기 위해 전부 보관해야 합니다.

활성화값의 크기는 매개변수 수에 비례하지 않고 `묶음 크기 × 련속 길이 × 층 수`에 비례합니다.

```
필요 현현기억기 총량 = (매개변수 수 × 12 바이트) + 활성화값
```

## 3. 매개변수당 바이트 수 상세 해설

### 3-1. 모형 가중치 — 매개변수당 2 바이트 (bf16)

가중치는 신경망의 "기억"입니다. 각 층의 행렬, 편향, 임베딩 등 모든 학습된 수치값이 여기 포함됩니다. `bfloat16`(bf16) 형식을 사용하면 수치 하나당 2 바이트가 필요합니다.

```
3억 5천만 매개변수 × 2 바이트 = 700 MB (0.70 GB)
```

### 3-2. 기울기 — 매개변수당 2 바이트 (bf16)

역전파(Backpropagation) 과정에서 손실 함수의 기울기(gradient)를 모든 가중치에 대해 계산합니다. 각 가중치마다 해당 기울기값 하나가 생성되므로, 기울기 저장 공간은 가중치 저장 공간과 동일합니다.

```
3억 5천만 × 2 바이트 = 700 MB (0.70 GB)
```

**왜 기울기가 필요한가?**  
가중치를 얼마나, 어느 방향으로 조정해야 손실이 줄어드는지 알려주는 정보입니다. 매 최적화기 갱신마다 이 값이 사용되고 다음 역전파를 위해 새로 계산됩니다.

### 3-3. 아담 최적화기 상태 — 매개변수당 8 바이트 (fp32 × 2)

아담(AdamW)은 단순히 현재 기울기로 가중치를 조정하는 것이 아니라, 과거 기울기의 이력을 두 가지 형태로 기억합니다:

**1차 모멘트 (기울기 이동 평균) — 4 바이트:**
```
m_t = β₁ × m_(t-1) + (1 - β₁) × 기울기_t
```
기울기의 방향을 안정화하여 진동을 줄입니다. (β₁ = 0.9)

**2차 모멘트 (기울기 제곱 이동 평균) — 4 바이트:**
```
v_t = β₂ × v_(t-1) + (1 - β₂) × 기울기_t²
```
각 매개변수별 학습률을 자동으로 조정합니다. (β₂ = 0.999)

두 상태 모두 수치 안정성을 위해 `float32`(fp32, 4 바이트)로 저장합니다. 따라서 최적화기 상태만으로 매개변수당 8 바이트를 차지합니다.

```
3억 5천만 × 8 바이트 = 2,800 MB (2.80 GB)
```

### 3-4. 활성화값 — 묶음×련속×층에 비례

순방향 계산 시 각 층은 입력을 받아 출력을 생성합니다. 이 출력값(활성화값)을 역전파 때 다시 사용해야 하므로 현현기억기에 보관해야 합니다.

```
활성화값 크기 ≈ 묶음 크기 × 련속 길이 × 은닉 차원 × 층 수 × 2 바이트

350M 모형 기준 (batch=8, seq=1024, n_embd=1024, n_layer=24, bf16):
= 8 × 1024 × 1024 × 24 × 2 바이트
= 402,653,184 바이트
≈ 7.80 GB
```

이 값이 매개변수 관련 기억보다 훨씬 크다는 점에 주목하십시오. 활성화값이 학습 기억의 주된 부담입니다.

## 4. 론리 계산 — 왜 3억 5천만이 한계인가

### 4-1. 350M 모형 — 정확히 들어맞음 ✓

**모형 구성:** `n_layer: 24, n_head: 16, n_embd: 1024`  
**학습 설정:** `batch_size: 8, seq_len: 1024`

```
───────────────────────────────────────────────────────────
 항목                계산                           결과
───────────────────────────────────────────────────────────
 가중치 (bf16)       350,000,000 × 2 바이트    =  0.70 GB
 기울기 (bf16)       350,000,000 × 2 바이트    =  0.70 GB
 아담 모멘트 (fp32)  350,000,000 × 4 바이트    =  1.40 GB
 아담 분산  (fp32)   350,000,000 × 4 바이트    =  1.40 GB
                                               ──────────
 매개변수 소계                                 =  4.20 GB

 활성화값 (bf16)     8×1024×1024×24×2 바이트   ≈  7.80 GB
                                               ──────────
 합계                                          ≈ 12.00 GB  ✓
───────────────────────────────────────────────────────────
 RTX 5070 한계: 12 GB   →   정확히 들어맞음
```

현현기억기를 약 100 % 사용합니다. 묶음 크기를 8 이상으로 높이면 활성화값이 늘어나 한계를 초과합니다.

---

### 4-2. 500M 모형 — 들어가지 않음 ✗

```
───────────────────────────────────────────────────────────
 항목                계산                           결과
───────────────────────────────────────────────────────────
 가중치 (bf16)       500,000,000 × 2 바이트    =  1.00 GB
 기울기 (bf16)       500,000,000 × 2 바이트    =  1.00 GB
 아담 모멘트 (fp32)  500,000,000 × 4 바이트    =  2.00 GB
 아담 분산  (fp32)   500,000,000 × 4 바이트    =  2.00 GB
                                               ──────────
 매개변수 소계                                 =  6.00 GB

 활성화값 (동일 설정)                          ≈  7.80 GB
                                               ──────────
 합계                                          ≈ 13.80 GB  ✗
───────────────────────────────────────────────────────────
 부족분: 1.80 GB  →  즉시 OOM 충돌
```

1.80 GB가 부족하여 학습을 시작하자마자 기억기 초과 오류가 발생합니다.

### 4-3. 1B (10억) 모형 — 크게 초과 ✗

```
───────────────────────────────────────────────────────────
 항목                계산                           결과
───────────────────────────────────────────────────────────
 가중치 (bf16)    1,000,000,000 × 2 바이트    =  2.00 GB
 기울기 (bf16)    1,000,000,000 × 2 바이트    =  2.00 GB
 아담 모멘트 (fp32) 1,000,000,000 × 4 바이트  =  4.00 GB
 아담 분산  (fp32)  1,000,000,000 × 4 바이트  =  4.00 GB
                                              ──────────
 매개변수 소계                                = 12.00 GB

 활성화값 (batch=16 기준)                     ≈ 10.00 GB
                                              ──────────
 합계                                         ≈ 22.00 GB  ✗
───────────────────────────────────────────────────────────
 부족분: 10 GB  →  RTX 4090 (24 GB) 수준이 필요
```

10억 매개변수 모형은 매개변수 소계만으로 이미 12 GB를 모두 소진합니다. 활성화값을 담을 공간이 전혀 남지 않습니다.

---

### 4-4. 왜 매개변수 소계가 12 바이트인가 — 자세한 설명

```
매개변수 하나가 학습 중에 차지하는 공간:

  가중치   ████  2 바이트  (bf16)
  기울기   ████  2 바이트  (bf16)
  모멘트   ████████  4 바이트  (fp32)
  분산     ████████  4 바이트  (fp32)
           ────────────────────────
  합계         12 바이트
```

아담 최적화기 상태가 fp32인 이유: 기울기 합산을 반복할 때 수치 정밀도 손실이 누적되면 학습이 불안정해집니다. 가중치와 기울기는 bf16으로 충분하지만, 최적화기 상태는 fp32 정밀도를 유지해야 합니다.

## 5. 기울기 재계산 기법으로 5억 5천만까지 확장

### 5-1. 원리

`torch.utils.checkpoint`는 순방향 계산 중 일부 층의 활성화값을 저장하지 않고, 역전파가 필요할 때 **다시 계산**합니다. 이를 통해 활성화값 기억을 약 절반으로 줄일 수 있습니다.

```
일반 학습:     모든 층의 활성화값 보관  →  기억 큼,    속도 빠름
재계산 기법:   활성화값 일부 재계산   →  기억 절반,  속도 약 30% 감소
```

### 5-2. 계산 — 550M 모형에 적용

```
───────────────────────────────────────────────────────────
 항목                계산                           결과
───────────────────────────────────────────────────────────
 가중치 (bf16)       550,000,000 × 2 바이트    =  1.10 GB
 기울기 (bf16)       550,000,000 × 2 바이트    =  1.10 GB
 아담 모멘트 (fp32)  550,000,000 × 4 바이트    =  2.20 GB
 아담 분산  (fp32)   550,000,000 × 4 바이트    =  2.20 GB
                                               ──────────
 매개변수 소계                                 =  6.60 GB

 활성화값 (재계산 기법 적용, 약 절반)          ≈  4.00 GB
                                               ──────────
 합계                                          ≈ 10.60 GB  ✓
───────────────────────────────────────────────────────────
 여유분: 1.40 GB  →  RTX 5070 12 GB에 들어맞음
```

재계산 기법을 켜면 속도가 약 30 % 느려지지만, 3억 5천만에서 5억 5천만으로 모형 규모를 키울 수 있습니다.

### 5-3. 활성화 기억이 왜 절반이 되는가

```
일반 학습:
순방향 → [층1 출력] [층2 출력] [층3 출력] ... [층24 출력] 모두 보관
역전파 → 각 층의 출력을 꺼내어 기울기 계산

재계산 기법:
순방향 → 중간 출력 일부만 보관 (예: 8층마다 하나)
역전파 → 필요한 출력값은 그 시점에 다시 계산하여 사용
```

저장량은 줄지만 계산량이 늘어나는 교환 관계(trade-off)입니다.

## 6. 현현기억기 규모별 학습 한계 비교표

| 현현기억기 | 표준 학습 최대 매개변수 | 재계산 기법 적용 최대 | 추론 최대 (4비트 양자화) |
|-----------|-------------------:|-------------------:|-------------------:|
| 4 GB | 3천만 (30M) | ~5천만 (50M) | 80억 (8B) |
| 8 GB | 8천 5백만 (85M) | ~1억 5천만 (150M) | 160억 (16B) |
| **12 GB (RTX 5070 ← 나의 그라픽 처리 장치)** | **3억 5천만 (350M)** | **~5억 5천만 (550M)** | **240억 (24B)** |
| 16 GB | 4억 5천만~5억 (450M~500M) | ~7억 5천만 (750M) | 320억 (32B) |
| 24 GB (RTX 4090) | 9억~10억 (900M~1B) | ~15억 (1.5B) | 480억 (48B) |
| 80 GB (A100) | 40억 (4B) | ~60억 (6B) | 1천 6백억 (160B) |
| 128 GB | 70억 (7B) | ~100억 (10B) | 2천 6백억 (260B) |

**핵심 규칙:** 추론은 학습보다 6~8배 더 큰 모형을 같은 현현기억기로 실행할 수 있습니다.

## 7. 추론이 학습보다 훨씬 저렴한 리유

모형을 실행하는 것(추론)과 훈련하는 것(학습)은 같은 하드웨어를 사용하지만 현현기억기에 저장하는 내용이 완전히 다릅니다.

| 현현기억기에 저장하는 것 | 학습 | 추론 |
|--------------------------|------|------|
| 모형 가중치 | ✓ bf16, 매개변수당 2 바이트 | ✓ bf16 또는 양자화 (더 작음) |
| 기울기 | ✓ 매개변수당 2 바이트 | ✗ 계산하지 않음 |
| 아담 최적화기 상태 | ✓ 매개변수당 8 바이트 | ✗ 필요 없음 |
| 모든 층의 활성화값 | ✓ 전부 보관해야 함 | ✗ 한 층씩 처리 후 즉시 버림 |
| KV 캐시 | ✗ 사용 안 함 | ✓ 어표 생성마다 증가 |
| **매개변수당 합계** | **~12~16 바이트** | **~0.5~2 바이트** |

**추론이 저렴한 핵심 리유:**

- **추론:** 한 층의 계산이 끝나면 그 층의 중간값을 즉시 버리고 다음 층으로 이동합니다. 현현기억기에는 항상 현재 층의 정보만 있으면 됩니다.
- **학습:** 역전파가 마지막 층에서 첫 층까지 거슬러 올라가며 기울기를 계산해야 합니다. 이를 위해 모든 층의 중간값을 순방향 계산 내내 보관해야 합니다.

## 8. 7B 모형을 실행은 하면서 학습은 못 하는 리유

이것이 가장 직관에 반하는 사실입니다. RTX 5070(12 GB)으로 70억 매개변수 모형을 대화에 사용할 수 있지만, 같은 모형을 처음부터 학습하려면 현현기억기 약 99 GB가 필요합니다.

## 9. 현현기억기를 늘리지 않고 한계를 밀어내는 조정 방법

RTX 5070(12 GB)에서 가능한 최대한 큰 모형을 학습하고 싶다면 아래 네 가지 방법을 조합할 수 있습니다:

### 방법 1: 묶음 크기 줄이기 — 활성화값 감소

```
묶음 크기 (batch_size) 16 → 8:  활성화값 약 절반으로 감소
묶음 크기 (batch_size) 8  → 4:  활성화값 약 1/4로 감소
```

실효 묶음 크기는 `grad_accum_steps`를 같은 비율로 늘려 보상합니다:
```yaml
# 변경 전
batch_size: 16
grad_accum_steps: 4
# 실효 묶음: 16 × 4 = 64

# 변경 후 (현현기억기 절반, 동일한 학습 품질)
batch_size: 8
grad_accum_steps: 8
# 실효 묶음: 8 × 8 = 64  (동일)
```

### 방법 2: 문맥 길이 줄이기 — 활성화값 감소

```
block_size 1024 → 512:  활성화값 약 절반으로 감소
block_size 1024 → 256:  활성화값 약 1/4로 감소
```

단, 긴 문맥을 학습하는 능력이 줄어드는 교환 관계가 있습니다.

### 방법 3: 기울기 재계산 기법 켜기 — 활성화값 절반

```python
# src/train/train.py에서 적용
from torch.utils.checkpoint import checkpoint

# 변환기 블록 순방향 계산을 재계산 기법으로 감쌈
output = checkpoint(transformer_block, x)
```

활성화값이 약 절반으로 줄고 학습 속도가 약 30 % 감소합니다.

### 방법 4: torch.compile 켜기 — 처리 속도 향상 (기억 절약 아님)

```yaml
train:
  compile: true
```

현현기억기는 절약되지 않지만 처리 속도가 약 15 % 향상됩니다. RTX 5070 Blackwell 구조에서 효과적입니다.

### 네 가지 방법 조합 효과

```
기본 설정:
  batch=16, seq=1024, 재계산 기법 꺼짐  →  최대 350M

조정 후:
  batch=8, seq=1024, 재계산 기법 켜짐   →  최대 550M
  batch=4, seq=512,  재계산 기법 켜짐   →  최대 700M (추정, 품질 타협)
```

이 방법들로 350M에서 550M까지 밀 수 있지만, `매개변수 수 × 12 바이트`라는 가중치·기울기·최적화기 합계의 기본 바닥은 극복할 수 없습니다.

## 10. 종합 요약

### 핵심 질문과 대답

| 질문 | 대답 |
|------|------|
| 왜 학습이 이렇게 많은 현현기억기를 쓰는가? | 가중치 + 기울기 + 아담 상태 + 모든 층 활성화값을 동시 보관 → **매개변수당 12 바이트** |
| 왜 학습보다 더 큰 모형을 실행할 수 있는가? | 추론은 기울기·최적화기 상태·중간 활성화값을 저장하지 않음 → 매개변수당 약 2 바이트 |
| RTX 5070(12 GB)의 학습 한계는? | 표준: **3억 5천만 매개변수** / 재계산 기법 적용: **~5억 5천만 매개변수** |
| 10억 매개변수 모형을 학습하려면? | 24 GB 그라픽 처리 장치 (RTX 4090, RTX 3090) |
| 70억 매개변수 모형을 학습하려면? | A100 80 GB 카드 4~8장 (총 320~640 GB 현현기억기) |
| 현현기억기 추가 구입 없이 한계를 늘릴 수 있는가? | 묶음 크기 줄이기 + 문맥 길이 줄이기 + 기울기 재계산 기법으로 350M → 550M까지 가능 |

### 한 줄 요약

> RTX 5070은 현현기억기 12 GB로 매개변수당 12 바이트를 학습에 사용해야 하므로,  
> 활성화값을 포함하면 3억 5천만 매개변수가 물리적 상한선입니다.  
> 기울기 재계산 기법으로 이를 5억 5천만까지 늘릴 수 있지만,  
> 그 이상은 더 큰 그라픽 처리 장치가 있어야만 가능합니다.
